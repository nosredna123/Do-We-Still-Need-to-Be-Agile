## Composite-Key Validation (`ID_Equipe`, `Semestre`)

All 14 team-semesters (`TEAM_01`…`TEAM_05`, `TEAM_07`…`TEAM_10` for 2025.2;
`TEAM_01`…`TEAM_05` for 2026.1) are present in every lake dataset that carries
the composite key: `git_team_cuts`, `evaluator_team_cuts`, `git_commits`,
`git_files`, `git_repository_snapshots`. Verified against real data via
`paper_v9.scripts.common.validate_keys.validate_team_semester_keys` — zero
keys missing from any dataset, zero unexpected keys.

## Checkpoint (T1/T2/T3) Coverage Gaps

Of the 42 possible (team, semester, checkpoint) combinations, 9 have no
observed git activity in `git_team_cuts` (this matches
`data/lake/lake_validation_report.json`'s `evaluator_keys_without_git`
exactly): TEAM_01/2025.2/T2, TEAM_02/2025.2/T1, TEAM_03/2025.2/T1+T2,
TEAM_04/2026.1/T2, TEAM_05/2025.2/T1+T2, TEAM_08/2025.2/T1, TEAM_10/2025.2/T1.
These are genuine "no repository activity observed" cases, not a validation
defect — metrics must report them as `unavailable_not_measured`, never as
zero.

## Transcript Coverage Gap

`transcript_sessions.parquet` only covers semester **2025.2**. Semester
**2026.1** has zero transcript sessions. M5 (coordination-friction evidence)
must declare 2026.1 as `unavailable_not_measured` for that metric family and
must not interpolate or borrow evidence from 2025.2.

## Artifact / Code-Churn Policy

- Single source of truth: `pipeline_config.is_measurement_code_path`.
- Current policy version: `code-churn-metrics-v2` (`cc_definition_version`:
  `cc-v2-clean-paths`), matching `data/analysis/code_churn_metrics.parquet.metadata.json`.
- Adapted (not duplicated) in `paper_v9/scripts/common/artifact_policy.py`;
  M4/M8 must call `assert_current_code_churn_contract` before consuming any
  code-churn artifact and must fail fast on stale (`v1`) or missing versions.
- Excluded path patterns and source-code extension allowlist are read
  directly from `pipeline_config` at inventory-build time — never
  hand-copied — so this document and the manifest cannot drift from the
  actual policy.

## Comparison with V8 Baseline

`paper_v8` used the same lake/policy contracts frozen in Task 0.2
(`paper_v9/data/manifests/v8_baseline_manifest.json`). No new data sources
were introduced for v9; the same 14 team-semesters, same code-churn policy
version, and same composite-key contract apply. The only structural
difference vs. the v8 metric scripts is that v9 wraps the same underlying
`pipeline_core`/`pipeline_config` primitives through the `paper_v9.scripts.common`
layer (Task 1.1) instead of importing them directly.
