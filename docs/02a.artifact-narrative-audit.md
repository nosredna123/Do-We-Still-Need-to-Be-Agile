# Intermediary Phase: Artifact Narrative Audit

**Status:** planning. This phase runs after Phase 2 (concluded) and before Phase 3
(`docs/02.phase2.md`, `docs/00a.general-plan.md`). It does not change any
Phase 2 contract, script, or artifact; it only reads them.

**Objective:** before writing theoretical grounding (Phase 3), produce a
didactic, English-language, LLM-assisted explanation of every Phase 2
analytical artifact, explicitly bind each artifact to the narrative arc
(`docs/00b.narrative-arc.md`), and issue an evidence-based verdict on whether
the current asset set is statistically and narratively sufficient to support
the thesis of `docs/00a.general-plan.md`. If the verdict is negative or
conditional, this phase must say so plainly and point to what would need to
change (more repositories, more teams, more semesters, relaxed claims, etc.),
rather than let Phase 3/4 rationalize weak evidence after the fact.

This phase exists because the current numeric picture is thin and must be
confronted directly, not narrated away:

- `team_metrics.parquet` has **14 team-semester rows** total.
- The four primary correlations
  (`data/analysis/correlation_results.csv`) are: `pi_vs_cc_primary`
  (ρ = -0.007, p = 0.98, n = 14), `pi_vs_delta_dt_primary` (ρ = -0.015,
  p = 0.96, n = 14), `ai_vs_cc_primary` (ρ = 0.214, p = 0.64, n = 7, flagged
  `small_sample_n_lt_10`), and `context_ie_temporal_primary`
  (`status = unavailable`, `reason = zero_variance`, n = 3).
- The three primary hypothesis tests
  (`data/analysis/hypothesis_results.csv`) show p ≈ 0.71 and p = 1.0 for the
  two that ran, and `status = unavailable` (`insufficient_group_n`) for the
  IE comparison.
- None of the four primary statistical tests that actually ran are
  significant, and one of four is not even computable given current data.

The narrative reports produced by this phase must state this plainly instead
of hiding it behind aggregate visuals, and the go/no-go verdict must be
grounded in these numbers.

## Why a new phase instead of folding this into Phase 3

Phase 3 (`docs/02.phase2.md` § Fase 3) assumes empirical results are already
understood and only need literature triangulation. Right now the results are
generated but not yet interpreted, checked for narrative fit, or judged for
sufficiency. Skipping straight to literature triangulation risks anchoring the
discussion on numbers nobody has scrutinized for validity, sample size, or
alignment with the four acts. This phase closes that gap without touching
Phase 2 code.

## Deliverable Shape (three layers, all Markdown, all English)

### Layer 1 — Per-artifact reports

One Markdown file per artifact listed above, generated at
`data/analysis/artifact_reports/<artifact_id>.md`, each covering:

- **What it is:** granularity/unit of analysis, row count, key columns,
  producer script, contract version.
- **How it was built:** one-paragraph plain-language summary of the
  computation (no re-deriving the math, just orienting a reader).
- **Narrative binding:** which act(s) of `docs/00b.narrative-arc.md` this
  artifact serves, and which specific claim in `docs/00a.general-plan.md` it
  is meant to support or falsify.
- **What the current data actually shows:** concrete numbers pulled from the
  artifact itself (n, missingness, key statistics, exclusion counts) — not
  paraphrased from the spec.
- **Contribution assessment:** does this artifact currently support,
  contradict, or stay inconclusive about the thesis, and why (tie back to
  sample size, significance, missingness, variance).
- **Known limitations:** carried over from `*_exclusions.json`,
  `*_unavailable_reason` fields, and manifest warnings — never invented.

### Layer 2 — Narrative-act synthesis reports

One Markdown file per act, at
`data/analysis/artifact_reports/act_<n>_<slug>.md` (four files, matching Ato
1–4 of `docs/00b.narrative-arc.md`), each aggregating the Layer-1 verdicts of
every artifact feeding that act and stating whether that act is currently
empirically supported, partially supported, or unsupported by Phase 2 data.

### Layer 3 — Consolidated audit report and verdict

A single `data/analysis/artifact_reports/00_consolidated_audit.md`, checksummed
and versioned like every other Phase 2 output, that:

- Indexes all Layer 1 and Layer 2 reports.
- Restates the full evidence table (all correlation/hypothesis rows, n,
  p-values, status) in one place.
- Gives an explicit **go / conditional-go / no-go** verdict on proceeding to
  Phase 3 as currently scoped, with the specific reasons (e.g., "n=14 teams
  is insufficient for any of the four primary tests to reach significance;
  Phase 3/4 must frame findings as exploratory/descriptive, not confirmatory,
  unless more repositories/semesters are added first").
- Lists concrete remediation options if the verdict is conditional/no-go
  (e.g., collect additional semesters, relax to exploratory case-study
  framing, add repository-level covariates, expand qualitative triangulation
  to compensate for low quantitative power).

## Proposed Producer: `07_artifact_narrative_reporter.py`

Following Phase 2 conventions (fail-fast, versioned prompts, checksum-based
resume, mock backend for tests):

- **Entry point:** new `run_pipeline.py` stage `"narrative-audit"`, appended
  after `"stats"` in `STAGES`/`STAGE_SCRIPTS`. It is part of the **default**
  stage tuple, so a full `run_pipeline.py` run (no `--stages` filter) always
  attempts to generate any missing/stale report. It can still be excluded
  explicitly with `--stages` or a `--to-stage` cutoff before it.
- **Figures get their own Layer-1 reports too:** each of the five prioritized
  figures (`pi_vs_cc`, `cc_by_temporal_cut`, `delta_dt_by_team_semester`,
  `ai_before_t3`, `ie_by_cut_or_corpus`) is treated as an individually
  reported artifact, sourced from its `figure_manifest.json` entry and its
  `figure_data/*.csv`, not folded into one generic "figures" report.
- **Verdict exit code:** the `narrative-audit` stage always exits `0`
  regardless of the go/conditional-go/no-go verdict. The verdict is a
  human-facing judgment recorded in the consolidated report, not a CI gate;
  `run_pipeline.py` must not treat a `no-go` as a stage failure.
- **Inputs:** reads only artifacts and sidecars listed in Scope, directly from
  disk; validates `status: success` and sidecar presence before using any
  artifact, exactly like `06_statistical_analyzer.py` does for its inputs.
  Fails fast if a required artifact or sidecar is missing/stale.
- **LLM usage:** one prompt template per layer
  (`ARTIFACT_REPORT_PROMPT_VERSION`, `ACT_SYNTHESIS_PROMPT_VERSION`,
  `AUDIT_VERDICT_PROMPT_VERSION`), defined in `pipeline_prompts.py`, with
  concrete extracted numbers (not raw PII, not free-text survey answers)
  injected into the prompt as structured context. The LLM's job is to write
  the didactic prose and judgment paragraph; it must not invent numbers — the
  script computes and injects every statistic used in the report.
- **Backend:** reuse `llm_gateway.py` and support `--nlp-backend
  {openai,mock}` the same way `04_nlp_qualitative_miner.py` does, so tests run
  offline deterministically.
- **Reproducibility and cost control:** each generated Markdown report gets
  its own sidecar `.metadata.json` (`input_checksum`, `status`,
  `prompt_version`, `model`, `contract_version`). Skip/resume is evaluated
  **per individual report file**, not per stage run: if a specific report and
  its sidecar already exist with `status: success` and a matching checksum of
  its own inputs (its source artifact(s), sidecar(s), and prompt version),
  that single report is skipped and no LLM call is made for it, even if other
  reports in the same run are stale or missing. `--force` bypasses this only
  for explicitly targeted reports (or all, if no target is given), never as a
  blanket rewrite of untouched reports. This is the primary mechanism to
  minimize LLM API spend on repeated runs.
- **No raw PII/text leakage:** reports may quote aggregate statistics and
  enum/category labels already present in public artifacts, never
  `answer_text`, `evidence_summary_private`, or other private fields.
- **Testing:** `tests/test_phase2_narrative_audit.py` (or similarly named)
  with a mocked LLM backend, covering: missing artifact fails fast, stale
  sidecar triggers regeneration, verdict correctly reflects injected
  significance/n numbers, and no private fields reach the prompt payload.

## Decisions Confirmed

- Consolidated verdict report: `data/analysis/artifact_reports/00_consolidated_audit.md`.
- Verdict never fails the build; `narrative-audit` always exits `0`.
- Each of the 5 prioritized figures gets its own Layer-1 report.
- `narrative-audit` is part of the default `STAGES` tuple (runs automatically
  on a full pipeline run, generating only what's missing/stale).
- Skip/resume granularity is per individual report file, to minimize LLM
  spend; a stale or missing report never forces regeneration of unrelated
  up-to-date reports.
